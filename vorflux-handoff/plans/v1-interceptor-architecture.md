# v1 — Interceptor Architecture Master Program (requestr)

### Summary

This is the integrated, dependency-ordered execution plan for the full interceptor architecture in `Mahesh953-hub/requestr` (branch `vorflux/fix-audit-gaps`, `b71d61f`). It merges four lane subplans (transport/MITM, persistence/protocol/export, rules/breakpoint/scripting/replay, UI/responsive tabs) into one program with a single schema ledger, one set of file boundaries, one release-slice order, and one verification matrix. Every claim about current behaviour below was read from source; audit contradictions were resolved against source, and audit percentages and effort-hour figures are discarded. Scope is everything the dossier specifies that is actually missing or partial — no stubs, no simplified substitutes, no legacy-preserving compromises, and no deferred "future work" placeholders. The program is **67 dependency-ordered tasks** across **nine slices (S0–S8)**, closed by **30 quantitative gates**, over a **six-version schema ledger (v19–v24)**, under **14 locked decisions**, with **three deliberate exclusions** and no open questions.

## 1. Approved decisions (locked — not open questions)

| # | Decision | Consequence in this plan |

| D1 | **Vendor a focused, pinned tun2proxy fork** with authenticated SOCKS5 carrying `+info`, virtual DNS, packet tee, explicit UDP/443 policy, protected sockets, and stable JNI events | Replaces the current `tun2proxy = "=0.8.3"` HTTP-proxy wiring that drops all UDP and delivers IP-only CONNECTs; unlocks hostnames, UID attribution, DNS, PCAPng and passive QUIC decode in native-bridge mode |

| D4 | **Use a Room-compatible bundled SQLite runtime so FTS5 is guaranteed**; migrate legacy flattened WS/gRPC rows; ship **native PCAPng**; ship **all 20 snippet targets**; **Report Server is in scope** | FTS5 with `tokenize='unicode61'` as the dossier specifies (not an FTS4 substitute); no legacy rows left behind; export surface complete |

| D6 | **QUIC/UDP policy is scoped to the capture selection.** Packages **outside** the capture scope, or explicitly bypassed, **pass UDP untouched** — never teed, never dropped, never recorded. For **selected capture targets** the default is **tee then drop UDP/443**, forcing an honest HTTP/2 fallback; an **Observe-QUIC override** tees then **passes** the datagrams and decodes only when session keys are proven. ## 4. Reconciled schema ledger and migration sequencing

Current shipped version is **18** (`RequestrDatabase.kt:98`, schemas `app/schemas/*/8.json … 18.json`, migrations `MIGRATION_8_9 … MIGRATION_17_18` registered at `:149`). The two lanes' overlapping proposals are reconciled into one strictly increasing ledger; each version is one reviewable migration with its own Robolectric test following the existing `MigrationXToYTest` pattern.

| Version | Owner | Contents |
|---|---|---|
| **v19** | Persistence | `transaction_headers` (`trafficId` FK CASCADE, `kind` = REQUEST/RESPONSE/TRAILER/PSEUDO, `ordinal`, `name`, `value`; indices on `trafficId`, `name`) — duplicate- and order-preserving; `transaction_timings` (`trafficId` PK FK, nullable `dnsMs`, `connectMs`, `tlsMs`, `sendMs`, `waitMs`, `receiveMs`, `totalMs`, no `-1` sentinels); `applied_rules` (`trafficId` FK, `ruleId`, `ruleName`, `stage`, `phase`, `outcome`, `detail`, `appliedAt`; index `trafficId`); body-reference columns on `captured_traffic` (`requestBodyFilePath`, `responseBodyFilePath`, `requestBodySha256`, `responseBodySha256`, `requestBodyPreview`, `responseBodyPreview`, `requestBodyStoredBytes`, `responseBodyStoredBytes`, `requestBodyTotalBytes`, `responseBodyTotalBytes`); `saved_api_requests.protocolPreference` (`AUTO`/`H1`/`H2`/`H3`, default `AUTO`) plus `captured_traffic.negotiatedProtocol` and `protocolDowngradeReason` for API-Testr H3 (tasks 58–60) |
| **v20** | Persistence | `websocket_messages`, `sse_events`, `grpc_messages`, `http2_stream_events` (all FK CASCADE to `captured_traffic`, indexed on `trafficId` and `timestamp`/`streamId`) |
| **v21** | Persistence | One-time backfill of legacy flattened rows: `method = "WS→"/"WS←"` rows become `websocket_messages` children of a synthesized parent flow per connection; `x-grpc-*` pseudo-header rows become `grpc_messages` + trailer rows; converted parents are stamped so the backfill is idempotent |
| **v22** | Persistence | FTS5 virtual table `traffic_fts(traffic_id UNINDEXED, url, host, headers_text, body_text, tokenize='unicode61')` plus insert/update/delete triggers and an eager population pass over existing rows |
| **v23** | Rules | Typed rule tables: `interceptor_rules` (matcher spec + sealed stage config + `stage`, `sortOrder`, `folderId`, `enabled`, `legacyRuleId`), `rule_folders`, `breakpoint_paused_flows`, `replay_jobs`, `replay_results`; data-carrying backfill of every `intercept_rules` row (`createdAt` order → `sortOrder`, `replacementValue` JSON decoded into typed config by the shared converter); `intercept_rules` retained read-only |
| **v24** | Rules | Drop `intercept_rules` after all eight legacy consumers are cut over and the rule-parity gate (G6/G16) is green |

Reconciliation notes, so nothing is migrated twice: the persistence lane does **not** add `intercept_rules.order_index`/`folder_id`/`rule_folders` (D8) — ordering and folders exist only in `interceptor_rules`. The rules lane does **not** create `applied_rules` — it writes into the v19 table. FTS5 requires the bundled SQLite runtime (task 3) to be in place before v22 runs.

**Room + FTS5 mechanics.** Room 2.7.0 has `@Fts3`/`@Fts4` only, so `traffic_fts` is created and maintained by raw SQL inside the migration and queried through `data/search/TrafficFtsDao.kt` using `@RawQuery`/`SupportSQLiteQuery`. Room's identity validation covers declared entities only, so the undeclared virtual table does not break `MigrationTestHelper`; a dedicated test asserts trigger sync and query results. FTS5 availability is guaranteed by the bundled runtime, not by the device's system SQLite (`minSdk = 24`).

**Rollback and recovery.**

- Every migration is additive (nullable columns, new tables) except v24, which is gated on parity evidence and runs only after two shipped slices of dual-write-free operation.
- `data/persistence/DbBackup.kt` copies the database to `databases/requestr-pre-v<N>.bak` immediately before the first migration of a slice and keeps it until the first clean post-migration launch.
- The Room builder ships `fallbackToDestructiveMigrationOnDowngrade()` from slice S0 onward, so an APK rollback can never brick the app; when a downgrade wipe is detected the backup is restored and the event is reported in diagnostics.
- Body spill lives at `filesDir/captures/<sessionId>/<trafficId>.<req|res>.bin`; a startup sweep deletes orphans, session delete and pruning delete files transactionally with rows, and a missing file renders "body evicted" rather than failing.
- Failure semantics: migration failure rolls back and stays on the previous version with a visible error; spill write failure sets the truncated flag and keeps the row; write-queue saturation drops oldest with a metric and a UI warning, never blocks a relay; FTS insert failure degrades to the non-indexed query path; quota exceeded pauses capture with a user-visible event.
- The vendored native fork ships behind `nativeBridgeFork` for one slice with the pinned upstream 0.8.3 build retained as the fallback artifact; the legacy `TunRelay` path is retired only after parity evidence (D2).

## 10. Explicitly excluded, with evidence

**Already complete — no work item created:** `specialUse` FGS with subtype property (`AndroidManifest.xml:71`); classic PCAP writer (`PacketCaptureEngine.kt`, `PacketPump.kt:341/449`); Cronet engine with QUIC enabled (`runtime/http/CronetInstrumentation.kt`, `HttpStackDetector.kt:45`); `onRevoke` (`RequestrVpnService.kt:591`); UID APIs (`MitmProxyEngine.kt:524`, `ProcNetUidResolver.kt`); HTTP/1.1 chunked trailer-section parsing (`HttpParser.kt:269–308`); WebSocket and gRPC capture in some form (`CaptureEngine.kt:118/392–411/493/510`); `DiffView.kt` and `DiffViewHelpers.kt`; the HTTP/3, TLS-failure, relay-health, stack-fingerprint and CDP honest-state components; Rhino instruction ceiling plus wall-clock deadline (`JsScriptEngine.kt`); chaos bounds (`ChaosInjector`, `MAX_CHAOS_DELAY_MS`); `computeReplaySchedule`; the closed metadata-header allow-list; and the 23-test QUIC / QPACK-conformance / protobuf codec suites. (`FridaCaptureEngine.kt`, `runtime/frida/*` and `RootModuleGenerator.kt` exist but are **not** excluded — they are the starting point for tasks 63–65.)

**Deliberately excluded — exactly three items, each with a reason:**

1. **Active QUIC/HTTP-3 MITM.** Dossier D.1 treats it as an open problem, and Reqable does not do it either — its SOCKS5 UDP proxy blocks HTTP/3 so clients fall back to h2. D6 reproduces that behaviour with capture-scope safety, tee-first passive decode, and honest blocked/observed/decoded states, and the Frida tier (task 63) plus SDK keylogs supply real decryption where keys can be obtained. Nothing else in the program depends on active QUIC MITM.
2. **eBPF-based capture.** Requires kernel support and privileges that no shipping Android device grants a normal app; the transparent-redirect tier (tasks 48–49) covers the same use case on rooted devices.
3. **Emulator VPN/tun capture.** Redroid cannot create the interface (`Cannot create interface`, empty `pm list features | grep -i vpn`, AppOps uid mismatch; `/dev/net/tun` presence and the consent dialog are documented non-signals). Proxy mode is the supported emulator path, task 67 says so in-app, and this never blocks a release.

Everything else the dossier names — including Frida hook expansion, rooted system-CA trust, and Xposed as a detected optional adapter (Phase 7) — is in scope in this program (D13, tasks 63–66).
