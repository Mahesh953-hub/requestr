# requestr v3.6 — Rules Engine + VPN Hot-Reload

## What's New

### Rules Engine — All Actions Execute (Critical Fix)
Previously only BLOCK worked. Now all 5 rule actions are live:
- **BLOCK** — drops the transaction entirely (never persisted)
- **REDIRECT** — rewrites request URL from rule's `replacementValue`
- **MODIFY_REQUEST** — transforms request headers/body via JSON config
- **MODIFY_RESPONSE** — transforms response status/headers/body via JSON config
- **LOG_ONLY** — force-persists tagged traffic even when capture toggle is off

### VPN Filter Hot-Reload (Critical Fix)
Changing the app filter (which apps to capture) while capture is running now takes effect immediately. Previously required stop/start. The VPN tunnel tears down and re-establishes with the new filter automatically.

### Frida Chip Honesty
The Frida capability chip now shows "Detected (CLI only)" instead of "Running" when frida-server is reachable. The description clarifies that in-app Frida injection is not yet implemented — use Frida CLI from your workstation.

### From v3.5.1 + v3.5.2 (included in this release)
- Music screen now actually scans MediaStore on open (was never called — tracks stayed empty)
- Theme selector: SYSTEM mode highlights correctly, swatches filtered by mode (no overlap)
- CA export: fixed path `Downloads/requestr/requestr-ca.pem`, added `.0`, `.cert`, `.p12` formats
- 5 default intercept rules seeded on first launch (ad blockers, analytics, auth loggers)
- Add Rule form with all fields (name, regex pattern, domain, action selector, enabled toggle)
- Rules now persist to Room (were in-memory only — lost on restart)
